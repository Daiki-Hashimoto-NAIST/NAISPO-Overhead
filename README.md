# NAISPO-Overhead

「もぐもぐ モンスター」は、精霊に好物を届け、ごはんから生まれる光で眠ったランタンを起こすUnityの実験プロジェクトです。舞台は、青い夜景に囲まれたガラス張りの小さなお部屋。光が集まると、木の柱や床、葉が暖かく照らされます。背景・木の枝・食べ物・2匹の精霊には、提供された手描き風の画像を使っています。

Kinectの「見下ろし」と「正面」を設定画面で切り替えられます。見下ろしでは体の回転、正面では左右の手の高さで棒を操作します。既存の[NAISPO](https://github.com/Daiki-Hashimoto-NAIST/NAISPO)とは独立しています。

起動直後はKinectを使わないデモです。天井や机の上にKinectを固定した状態での認識精度・遊びやすさは、まだ実機で検証していません。

## 起動方法

Windows 64bitとUnity **6000.6.5f1** を使用します。

1. 正面モードを使う場合は、最初に `Setup-BodyTracking.cmd` を実行し、骨格認識モデルを準備します。モデルはGitに含めていません。デモと見下ろしだけなら、この手順は不要です。
2. このプロジェクトをUnityで開きます。
3. メニューの `Overhead / Build Windows` を選びます。
4. ビルドが終わったら、プロジェクト直下の `Run-Overhead.cmd` を実行します。

ビルド先は `Builds/Windows` です。実行時は `Launch-Overhead.ps1` が `%USERPROFILE%\NaispoOverheadRuntime` にコピーして起動します。Kinectのライブラリを日本語を含むパスから実行する問題を避けるため、コピー先は半角英数字だけのパスにしています。Windowsのユーザー名に日本語がある場合は、スクリプトの `runtimeFolder` を変更してください。

ビルド済みの実行ファイルはGit管理に含めていません。

## 遊び方

画面中央の枝を傾け、上から落ちてくる食べ物を左右の精霊に届けます。いちごは左、さかなは右の精霊が正解です。足元の絵が、それぞれの好物を表しています。起動直後は2行の案内と「はじめる」ボタンの画面です。ボタンか `Space` / `Enter` で始まり、遊び直しの「もういちど」は案内を挟まず直接再開します。

食べ物は、いちご2個・さかな2個をひと組にしてランダムな順番で出てきます。組の境目も含めて、同じ種類は最大2個まで続きます。最初の食べ物も固定ではなく、遊び直すたびに順番を選び直します。

食べ物が落ちる約0.65秒前に、ランタンの下へ食べ物の絵が小さく現れ、種類と位置を知らせます。一時停止を挟んでも、予告した食べ物は変わりません。食べ物はゆっくり回転しながら落ち、棒で弾くとぷにっと変形して、小さな音と光が出ます。

落下位置はランタンの左・中央・右をランダムな順番で使い、毎回少しずらします。同じ場所が続かないようにし、棒を大きく傾けたときも受けられる範囲に収めています。棒を回している途中の接触も判定し、弾いた直後でも再び触れれば受け止めます。一度棒で受けた食べ物は、端から離れて戻れなくなったら、その側のモンスターの口へ運びます。弱く弾いて飛距離が足りなくても届きますが、好物かどうかの判定は変わりません。

精霊は待っている間もゆっくり体を揺らし、食べ物が近づくと身を乗り出します。好物を食べると、もぐもぐしたあとに少ししゃがみ、一度跳ねて柔らかく着地。頭上にはハートが出て、ふたりとも目を閉じた笑顔になります。違う食べ物なら、ふたりとも丸い口のきょとんとした顔になり、ゆっくり首をかしげます。絡まった糸のアイコンも合わせて困惑を表し、反応が終わると通常顔に戻ります。左右で動くタイミングを少し変えています。

好物を届けるたびに、精霊の口から光がひとつ飛び、中央のランタンへ届きます。中央が元気になるにつれ、柱に取り付けた左右4つのランプも内側から外側へ明るくなります。光は1個ずつ積み重なり、小休憩を挟まず変化が続きます。10個で中央のランタンが目覚め、そのまま20個まで遊べます。左右どちらの精霊への成功でも部屋全体が明るくなり、一度灯った場所はそのまま残ります。20個目の光が届くと中央のランタンが少し浮き上がり、完成の余韻のあいだは枝と落下中の食べ物を止めます。

中央に光が届くと短い光の輪が広がり、そのあとも明るさが残るため、進んだ分だけ部屋が変わって見えます。20個の完成時は、ふたりの喜ぶ余韻も少し長めです。ランタン本体には手描き風の画像を使い、顔はプログラムで描いています。

20個届けると食べ物の落下が止まって「ランタンが おきた！」と表示されます。「もういちど」で最初の部屋から遊び直せます。時間制限はなく、失敗しても灯りは消えません。遊び直すと室内の明かりと蝶が消え、中央のランタンが眠っている状態に戻ります。喜んで手を下ろしても、点灯とお祝いの演出は最後まで進みます。

中央の金色のランタンは、最初は鼻ちょうちんをゆっくり膨らませて眠っています。少しずつ薄目を開け、10個目の光が届いて明るさが落ち着くと、ぱっちり目を覚まします。その後は仕分けに表情で反応しながら、部屋の完成を見守ります。開始前も寝息は動きますが、食べ物や得点は進みません。

窓の外の夜空は青いまま保ち、室内の柱・葉・床だけを暗い状態から暖かい明かりへ変化させています。カメラは固定です。精霊は暖かな赤と淡い青、仕分けの枝は金色の光をまとい、ランプが眠っている間も姿が見えます。精霊の輪郭から周囲へ柔らかく光が広がり、足元にも色が映ります。光は体の動きや枝の傾きに追従し、ゆっくり明るさが揺れます。表情や木目はそのまま見せています。食べ物や操作ボタンには暗さを重ねていません。以前の回廊のランプ列、壁飾り、星座と床の魔法陣は表示していません。背景と照明の設計は [GlassRoomDesign.txt](Documentation/GlassRoomDesign.txt) にあります。

正しく口まで届けた数は画面上部の星の横に表示します。操作説明は「ひとやすみ」で確認できます。Kinectの接続や細かい調整は、右上の「せってい」から開けます。音は設定画面の「おと：オン／オフ」で切り替えられます。設定画面と「ひとやすみ」では、動きと音が止まります。

| デモの操作 | 動作 |
| --- | --- |
| `A` / `←` | 左へ送る向きに傾ける |
| `D` / `→` | 右へ送る向きに傾ける |
| ゲーム領域で左クリックしたまま左右にドラッグ | マウスの横位置で傾きを変える |
| `ひとやすみ` | 一時停止する。`つづける` で再開 |
| `Escape` | 一時停止・再開。設定画面では設定を閉じる |
| `F11` または `せってい` → `全画面にする` | 全画面とウィンドウを切り替える。戻すと元のウィンドウの大きさに戻る |
| `せってい` → `はじめから` | 得点と食べ物、モンスターの表情をリセットする |

## Kinectで試す

先にNAISPOなど、Kinectを使っているアプリを閉じてください。右上の `せってい` で、カメラの向きを選びます。接続中に向きを切り替えると、カメラの処理を再起動します。自動切り替えは行いません。

### 正面から遊ぶ

1. Kinectを正面に置き、上半身と左右の手が映るようにします。
2. `せってい` → `しょうめん` → `Kinect をつなぐ` を選びます。空の背景を計測する必要はありません。
3. 両手を体の横に出し、左右に20 cm以上離します。プレビューに手首を結ぶ線が出ることを確認します。
4. `あそびに もどる` を押し、両手を上下に動かします。手首が同じ高さなら水平になります。肘を一直線に伸ばす必要はありません。

`ちかいところ` / `とおいところ` で、Kinectから両手首までの距離の範囲を変えられます。初期値は0.70〜3.50 mです。設定範囲内でも必ず認識できるわけではなく、カメラに映る範囲や手の隠れ方にも左右されます。

最初に追跡対象になった人を維持します。人を交代するときは、遊ぶ人がカメラの前に立ってから `あそぶ人を えらびなおす` を押してください。

### 見下ろして遊ぶ

Azure Kinect DKを真下に向けて固定し、床または机を映します。

1. `せってい` → `みおろし` を選び、床向けの `ゆか・からだ`、または机向けの `つくえ・て` を選びます。
2. 撮影範囲から人や手を出し、背景だけの状態にします。
3. `Kinect をつなぐ` を押し、30フレーム分の背景計測が終わるまでそのまま待ちます。
4. 床の場合は撮影範囲に入り、両腕を広げてゆっくり体を回します。設定画面のプレビューで、抽出された輪郭と、その向きを示す線を確認します。
5. `あそびに もどる` を押して遊びます。

カメラや背景を動かしたら、範囲を空けて `背景を とりなおす` を押してください。Kinectの入力中に `ゆか・からだ` と `つくえ・て` を切り替えたときも、背景を計測し直します。`マウス・キー` でデモに戻れます。

| 設定 | 内容 |
| --- | --- |
| `ゆか・からだ` | 背景との差が300〜2200 mmの部分を抽出 |
| `つくえ・て` | 背景との差が20〜250 mmの部分を抽出 |
| `ひくいところ` / `たかいところ` | 抽出する差の下限・上限を調整 |
| `左右反転` | 深度プレビューと入力軸を左右反転 |
| `回転反転` | ゲームへ伝える回転方向を反転 |

見下ろしの高さは「背景の深度 − 現在の深度」で求めています。正面モードの距離とは別の値です。真下向きの固定カメラを前提とした値で、床や机の傾きを補正する処理はありません。

## 認識の範囲

正面モードはAzure Kinect Body Trackingの左右手首を使います。カメラ座標の横位置と高さの差から `atan2(高さの差, 横位置の差)` で傾きを求め、表示の反転を適用して±65度に制限します。肘の角度や胴体の輪郭はこの計算に使いません。プレビューには深度画像上の手首の位置を結んだ線を表示します。

両手首の認識信頼度がMedium以上で、水平間隔が20 cm以上、両方が指定距離内にあるときだけ操作できます。片手を見失ったときや手が重なったときは、棒と食べ物を止めます。別の人へ自動で操作を引き継ぎません。新しい骨格結果が0.5秒以上届かない場合も停止します。手の遮蔽や交差が大きい姿勢まで保証するものではありません。

見下ろしモードは背景より手前にある部分を抜き出し、つながった領域のうち最大のものから、細長く伸びる向きを推定します（主成分分析）。こちらは骨格認識や手の識別をしないため、肘の曲がり方が推定する向きに影響することがあります。左右の手や、体の正面・背面も区別できません。

机で試す場合も、離れた両手を1組として扱う機能はありません。最大の領域だけを見るため、片方の手や腕の向きを試す用途です。

腕を閉じて輪郭が丸くなったときや、体の一部が隠れて軸を求められないときは、食べ物の動きを一時停止します。深度フレームが0.5秒以上届かない場合も停止します。近くの物が体とつながって映ると、推定する向きがずれることがあります。

SDKのライセンスは `Documentation/Licenses` に保存しています。同梱DLLのサイズとSHA256は、Sensor SDKが `Documentation/SDK_COPY_MANIFEST.json`、Body Tracking SDKが `Documentation/BODY_TRACKING_COPY_MANIFEST.json` に記録されています。

## 確認済みの動作

2026年10月30日、精霊の輪郭から周囲へ広がる光と床への照り返し、仕分けの枝を包む金色の光を加えました。魔法の存在らしさが伝わるように光の範囲と強さを調整し、ゆっくり明るさが揺れるようにしています。精霊の輪郭光と広い光は全表情分を起動時に用意し、プレイ中は再利用します。315件のEditModeテストとWindowsビルドが成功しています。デモで開始時の暗い部屋、左右に傾けた枝、表情の切り替え、部屋が明るくなったときの見やすさを確認しました。

2026年10月30日、光がランタンへ届いたときに重くなる照明処理を修正しました。部屋の形や光の届く範囲は起動時に計算し、プレイ中は同じ画像バッファの明るさだけを更新します。このPCのUnity Editorで51,840画素を32回更新して比較したところ、画素計算の中央値は従来198.812msから3.210msへ減り、更新中のメモリ割り当ては0バイトでした。比較した全画素の出力差は0で、暗さや色は変えていません。これは照明計算単体のCPU時間で、ゲーム全体のフレームレートではありません。315件のEditModeテストとWindowsビルドが成功しています。デモで成功後の照明、20個の完成、遊び直しでの消灯も確認しました。測定はUnityの `Overhead / Measure room lighting` で再実行できます。
